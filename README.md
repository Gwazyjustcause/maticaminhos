# MatiCaminhos

Portuguese delivery planner for restaurants, supermarkets, shopping centres, and unnamed delivery addresses. Default departure: Matisilva — Carnes Lda (40.1299257, -8.5240277).

Source: `Gwazyjustcause/maticaminhos`. Static site on GitHub Pages, with no package dependencies, API credentials, or ChatGPT sign-in.

## Development

Use Node.js 20+. `npm run dev` serves http://127.0.0.1:4173. `npm run check` checks syntax. `npm test` covers route optimization, costs, road access, per-leg toll preferences, route validation, postcodes, and whole-trip time. `npm run build` copies static files into ignored `dist/`. `npm run test:live` checks a real Matisilva–Leiria trip with tolls allowed and avoided. `npm run test:access` checks restaurant/building pins through road lookup, matrix optimization, and route geometry. Live checks make public routing requests and are deliberately separate from normal tests.

## Driver workflow

The map has **Mapa / Satélite** buttons. Street view uses OpenStreetMap; satellite view uses DGT's public OrtoSat2023 true-colour WMS (30 cm imagery for mainland Portugal, CC BY 4.0), with visible DGT attribution. No map API key or paid account is required. The chosen view is saved in the existing browser storage. Switching layers preserves the map position, zoom, route, delivery pins and entrance editor. Routes have a white casing for visibility over imagery. After repeated satellite tile errors, the app returns to street view and explains the failure. The imagery is a dated basemap, not a live feed; satellite coverage is mainland Portugal.

Search above the permanently visible map. Desktop shows the route and trip details in a scrolling left sidebar. **Moradas guardadas** toggles a separate panel to the right of the map; adding a saved stop leaves the panel open. On phones, the saved library temporarily replaces the scrolling route beneath the map. Phone shows the map above an independently scrolling route, so scrolling stops never hides the map. Search supports business names (e.g. Continente, Pingo Doce), shopping centres, addresses, Portuguese postcodes (including seven digits without a hyphen), latitude/longitude, and short or full Google Maps place links. Use the single search bar for a business plus city (for example, Continente Viseu), or a street plus town. Comma-separated street and town searches also work. Common street abbreviations such as R. and Av. expand before lookup.

Every forward request sets `countrycode=PT`, and results with any other country code (or no code) are rejected again locally. A supplied or inferred town is resolved before searching its area. Street-name tokens, administrative locality, and an optional house number are checked to prevent unrelated roads, wrong house numbers, or another municipality sharing the county name from appearing as matches. When needed, a structured street search is attempted. Requests are session-cached and spaced by at least 1.1 seconds.

Photon/OpenStreetMap results are not Google's complete business catalogue. Search also includes a small source-verified supplemental listing for Restaurante O Casimiro in Silveirinho / São Pedro de Alva, using the address and coordinates published on its own website: https://restauranteocasimiro.eatbu.com/?lang=pt. This is an explicit local catalogue entry, not a claim that the search provider now covers all missing Google businesses. Complete native Google business search requires a Google Places integration and API credential. A Google Maps lookup link lets drivers find missing places externally and paste the address or shared Maps link back into the planner. Short `maps.app.goo.gl`, older `goo.gl/maps`, `g.co/maps`, `g.page` and `share.google` links resolve through the free public [Mapu service](https://mapu.retiolus.net/), without an API key or account. Full coordinate-bearing URLs are decoded locally. Shared text containing a place name and a single link is accepted. When the URL only includes a camera centre, the resolver is used to find the business pin instead of silently importing the centre of the map. Routes and multi-place responses are rejected: import one delivery location at a time. Every import is reverse-checked for Portugal before the driver confirms its entrance.

Postcodes and street-level results can be approximate. Preview them on the map, drag the pin to the delivery entrance, and give the stop an optional custom name. If a named street cannot be found inside the supplied town (e.g. the reported Bela Vista / São João de Lourosa case), the app offers an explicitly labelled **locality-centre fallback, not an exact street location**. It cannot be added until the driver moves the pin. No search service guarantees every address or an exact entrance for a postcode.

Adding a stop does **not** add it to favourites. A heart explicitly toggles favourite status in search results, in the route, or when confirming a pin. Today's stops and the separate favourites library persist in local storage, as do vehicle and route preferences. Older saved data is preserved.

The interface calls this library **Moradas guardadas**. Persistent app data is stored in this site's browser `localStorage`, under `maticaminhos-v1`, on the current device/browser profile. There is no account database or device synchronization; clearing the site's browser data removes it. Geocoding and road-network requests still send search text/coordinates to the external providers described below.

Saved addresses can be assigned to a group from the **Grupo** selector beneath each saved address. **Todas** shows the full library, **Sem grupo** shows unassigned addresses, and the group filter shows counts. Initial groups are Restaurantes, Continente, and Pingo Doce; **Novo grupo** creates a custom group and **Renomear** changes its name. Existing addresses remain unassigned until the driver chooses a group. Group definitions and membership persist alongside saved addresses in the same local storage, and editing a saved stop preserves its group. Groups do not affect route order or clear-route behavior.

**Limpar rota** removes the current stops, per-leg overrides, calculated path while retaining saved addresses, depot, manual entrances on saved addresses, and vehicle/preferences. **Restaurar rota** reverses the last clear during the same page session, until another plan change. Clearing also cancels queued recalculation, closes location/search editors, removes delivery progress with the route, resets totals, and centres on the depot. It does not delete saved addresses or reset vehicle settings.

The main **Rota mais rápida** button suggests a visiting order from driving-time matrices and a heuristic solver, then calculates and draws that route in one action. It also works with a single stop. It does not guarantee the global optimum or account for live traffic. **Calcular rota** calculates the displayed order instead. Choose any destination position from the number selector on a stop (for example, 1 → 5), use Subir/Descer, or drag a stop on desktop. Order changes stay editable and do not start a routing request; the moved stop stays visible until the driver finishes arranging the list and presses Calcular rota. Clicking a stop name lets the driver rename it or move its entrance. After calculating a route, changes to stop locations, return, or toll preferences recalculate its durations and map geometry. Delivery time updates the total without another routing request.

Whole-trip duration includes all driving legs, service time at every delivery, and return to the depot if selected. The interface focuses on route planning and does not ask for a date or departure time. Google Maps navigation opens the next directed leg with its toll preference; it may choose different roads and change the estimate.

## Restaurant pins and road access

Business/search pins remain at their original coordinates. Before matrix optimization or route calculation, a batched Valhalla `/locate` request resolves every stop and the depot to a nearby car-accessible road candidate with minimum connected-network reachability. Motorway edges, ramps, and ferries are excluded as access candidates. The closest eligible candidate must be within 300 metres; the app never silently jumps a building pin to a distant road.

The same prepared road coordinates and correlation settings are used by both the time matrix and final route. Road-access points appear as small outlined circles, linked to the place pins with dashed lines that are informational, not extra driving segments. Navigation links target the road access. Cached routes include their resolved access coordinates in their key, so changing an entrance cannot reuse an old route. Access lookups are cached only in memory and refreshed after reload.

If the matrix returns an unavailable connection (for example, a destination-only supermarket access road), the app automatically checks that directed pair with the full driving-route service, using the same access and toll preference. It uses the verified duration for optimization and caches the geometry for the final route. It never substitutes straight-line times or silently allows tolls. The live access regression includes Pingo Doce Crujeiro in Trancoso in both directions with and without tolls.

Each stop has an **Acesso** control for adjusting its vehicle/loading entrance independently of the business pin. A manual entrance can be at most 1 km from the business and must correlate to a drivable road within 100 metres. Manual entrances persist with the stop and update an existing favourite without automatically favouriting anything. Moving the business pin clears its manual entrance. An unavailable access or unreachable matrix pair identifies the place that needs attention. Road tagging cannot establish the actual loading-gate location or physical gate availability; drivers can adjust the suggested entrance.

## Tolls and routing

Valhalla/FOSSGIS supplies driving-time matrices and full-resolution polyline6 geometry. Global Permit/Evitar applies to all legs, clearing older overrides. Each directed pair of adjacent places can override the global choice, including the return leg. Overrides are keyed to the coordinates of the exact origin and destination, not a list index: reordering cannot attach an old preference to the wrong connection. Newly adjacent pairs use the global choice. Optimization uses the appropriate matrix entry for each directed override.

Avoid requests use `use_tolls: 0` and `exclude_tolls: true`. Public-server support for hard exclusions varies. The app only accepts an avoid leg if the returned **leg summary explicitly says `has_toll: false`**. A toll-containing or unverifiable avoid leg fails with an explanation rather than silently reverting to a tolled route. This depends on OpenStreetMap toll tagging and does not guarantee current real-world charging conditions.

Requests are user-triggered, cached per directed pair/preference in memory, batched into at most six consecutive legs with the same mode, and spaced at least 1.1 seconds apart. Matrices are split into at most 10×10 cells to respect the public server's 100-cell limit; 26 locations use nine small comparisons per required preference. Each request identifies the application with `X-Client-Id: gwazyjustcause.github.io/maticaminhos`. These are public demo services, not a production SLA. For regular or expanded production use, arrange a supported provider or self-hosted service. The Valhalla maintainers request an app-use notice via GitHub Discussions before broad end-user rollout; no external messages have been sent on the user's behalf.

## Fuel and toll prices

The header provides a **Modo escuro / Modo claro** toggle. Matisilva’s orange (#ED5732) is paired with neutral light surfaces or dark grey surfaces (#242628 / #2E3134). The preference persists in the existing browser storage; saved groups and addresses are preserved.

The driver supplies consumption (L/100 km), fuel price (EUR/L), and toll class. No vehicle figures or current fuel prices are assumed. Fuel litres = route kilometres × consumption / 100. Fuel cost = litres × price.

Automatic toll **estimates** use the bundled `toll-data.json` catalogue: **203 tariff locations and 5,624 directed four-class fares**, plus fixed electronic/open-barrier prices. The November 2026 audit corrected 26 damaged imported fare rows, separated shared-plaza lanes, added southern Brisa tariffs, A7/A14/A21 and Douro Litoral section prices, A8/A15 matrices, electronic tolls and the Lisbon bridges. Each fare has source provenance; reverse-derived fares are identified separately. See [TOLL-AUDIT.md](TOLL-AUDIT.md) for evidence, coverage and unresolved gaps. This remains **an expanded catalogue, not certified nationwide completeness**. Figueiredo on A11, Grândola/A26, some internal A11 combinations and partial closed-system journeys still need verification. The source-specific 2026 dates are recorded in the data. Standard classes 1–4 include verified A41/A19/Leiria–Pousos class 3/4 exemptions; personal, resident and subscription discounts are not inferred.

After a route is ready, a background Valhalla `trace_attributes` POST inspects its exact encoded geometry using `edge_walk`. Crossing coordinates match reviewed plaza locations derived from OpenStreetMap/Geofabrik (ODbL). Closed-system entry/exit pairs use directed table fares; the estimate does not assume a return follows the same route. Trace requests share the routing queue and 1.1-second rate limit. Geometry results are cached in memory, and stale requests cannot update a replaced or cleared trip. Changing the vehicle class selects another tariff locally without another request.

The always-visible cost card has a class selector and a per-leg breakdown. A whole-trip toll amount and combined fuel total appear only when **every leg has a verified price**. A route reported entirely without tolls shows €0. Unknown crossings, missing entry/exit pairs, ambiguous plazas, missing fares, failed traces, or a leg beginning/ending inside a closed toll system remain unavailable; no partial sum is presented as a complete total. Adjacent lane nodes are deduplicated, while later visits remain separate. Every mapped crossing is inspected, including exit plazas on approach lanes tagged toll=false. Former gantries are skipped only when explicitly verified as free in the local catalogue. This includes the former A25 Albergaria gantry, abolished in 2026; it must not become an A1 entry/exit. IC24 Sul (the CREP/A1 connector) is priced separately from Grijó PV. The former “Sobre esta estimativa” section remains removed.

The government's calculator is used for **manual source checks**, not runtime pricing. Direct service calls were inconsistent (zero/error responses), and a route ending inside an A33 section returned zero while the full section correctly returned €0.35. Its A19/IC36 higher-class results also needed correction against the current exemption law. No paid API, secret, account, proxy, or backend is required by the static catalogue. Existing public routing-service availability limits still apply.

### Updating static toll data

Optional build-time Python dependencies: `pdfplumber` and `osmium`. Drivers and site builds do not require them. Download the official source PDF and the free Portugal PBF extract from the URLs in `toll-data.json`; keep these large source files outside Git. Then run:

```sh
python tools/import-toll-tables.py brisa-august-2026.pdf rates.json brisa-march-2026.pdf
python tools/import-atlantico-tables.py atlantico-2026.pdf atlantico.json
python tools/extract-toll-nodes.py portugal.osm.pbf nodes.json
node tools/build-toll-catalog.mjs rates.json nodes.json atlantico.json
npm test
npm run test:tolls
npm run build
```

The importers are specific to the reviewed 2026 layouts and must be reviewed if those change. Whole currency tokens are parsed before column matching so rotated headings cannot clip leading digits. The August PDF's stale southern 2025 heading is rejected; southern prices come from the March revision with a 2026 heading. Source PDF SHA-256 hashes are retained. Review station IDs, lane membership and direction in `tools/toll-stations.json`, fixed barriers and source evidence in `tools/toll-supplement.json`, and reviewed section graphs in `tools/toll-section-tables.json`. Section graphs must be trees and agree with overlapping published matrix cells. Update source/verification dates when replacing tariffs. OSM attribution and ODbL references remain in the catalogue. `npm run audit:tolls` checks every data record and reference journeys offline. `npm run audit:tolls:live` checks a wider set of actual motorway routes and writes local evidence to ignored `artifacts/toll-feasibility/live-audit.json`; it is separate from ordinary tests and obeys the public routing request interval. `npm run test:tolls` retains the original access/outbound/return regressions.

## Limits and privacy

Maximum 25 delivery stops plus departure and optional return. Internet is required for Photon, Valhalla, Leaflet CDN, and map tiles. Search text and/or coordinates are sent to the relevant public services. No live traffic, delivery windows, vehicle weight/height restrictions, cold-chain rules, or multiple-driver allocation is implemented. CSV export retains each leg's toll preference and navigation link. No credentials are included in the source.

Google Maps link resolution sends only the pasted Google URL to Mapu when its coordinates cannot be decoded locally. Successful resolutions are cached in browser session storage for up to 24 hours. Mapu publishes a limit of 30 resolution requests/minute and 1,000/day per client; availability is not guaranteed. Failure leaves the route unchanged and offers the original Google link, address entry and map selection.

Vehicle entrances are remembered separately from saved addresses, in the existing `maticaminhos-v1` browser storage. Both automatic road matches and driver-adjusted entrances survive a reload, clearing the route, and rediscovering the same business coordinates. Up to 1,000 entrances are retained. Older manual entrances attached to saved/current places are migrated. Changing an entrance invalidates its old road match; changing the business coordinates does not copy an entrance from a nearby shop. A driver can replace an entrance through **Acesso**.

Clicking a numbered map pin (or its vehicle-access marker) scrolls only the route sidebar to that stop and highlights it. Adding a stop reveals its card. Explicit calculation/optimization and completion of all deliveries return the sidebar to the trip summary at the top. On phones, selecting a pin reveals the route if the saved-address panel was open, while the map remains visible.

Place or reposition a delivery/entrance pin with a double-click (double-tap on touch devices). A single click on the basemap does nothing. Leaflet’s separate double-click zoom is disabled so placing a point does not trigger a competing zoom. Existing numbered pins still reveal their route stop with one click; marker dragging and the zoom controls remain available.

Search resolves the actual city/town before broader administrative boundaries with the same name and uses its mapped extent when available. Recognized supermarket-chain queries filter to supermarkets and reject charging stations, recycling bins, car parks and unrelated shops. Search remains Portugal-only. Background recalculations preserve the driver’s sidebar position; only explicit route calculation/optimization returns it to the top.
